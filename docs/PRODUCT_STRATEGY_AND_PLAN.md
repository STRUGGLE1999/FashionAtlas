# FashionAtlas 产品定位与项目计划

## 1. 重新定位

FashionAtlas 不应只是一个国外时尚网站跳转目录。更有竞争力的定位是：

> 面向中文时尚爱好者的全球时尚美学学习与资讯策展平台，帮助用户在不同兴趣、阶段和场景下知道该看什么、为什么看、怎么看，以及如何把资料转化为审美判断和穿搭灵感。

核心用户问题不是“哪里有链接”，而是：

- 我对时尚感兴趣，但不知道从哪里开始看。
- 我想提高审美，但不知道哪些书、电影、杂志、秀场值得看。
- 我看到一个趋势词或穿搭风格，但不知道它从哪里来、适合谁、怎么应用。
- 我想关注每周/每月趋势，但不想刷碎片化平台，也不想被卖货内容带偏。

因此，FashionAtlas 的竞争力应从“资源收录”升级为“中文策展判断 + 情境化推荐 + 趋势解释 + 个人灵感沉淀”。

### 已确认的产品取向

- 内容重心：学习型时尚资料站 60%，日常穿搭趋势资讯站 40%。
- 趋势频率：每周做穿搭趋势分析，每月做月度趋势分析。
- 趋势真实性：使用真实趋势，不做纯作品集虚构样例；每期趋势必须有来源依据。
- 资源类型：书籍、影片、纪录片、设计师传记、时尚电影、美学电影、时装秀、杂志、网站均可纳入。
- 目标用户：偏时尚小白/时尚爱好者，而不是专业院校申请者或行业从业者。
- 趋势地域侧重：偏中国用户日常穿搭语境，以国内真实穿搭观察为主，全球时装周/国际媒体趋势作为背景补充。
- 推荐清单范围：书籍、影片、杂志、秀场四类都做，不设第一批单一优先类目。
- 趋势内容边界：只做推荐分享和审美解释，不做价格分析、预算分层或购买替代单品推荐。
- 资料搜集方式：可以通过公开网页检索、爬虫或人工整理获取元信息、标题、来源链接和摘要线索，但不抓取/托管受版权保护的全文、PDF、视频、图片包或付费内容。

## 2. 用用户体验五层分析产品竞争性

### 战略层：为什么存在

用户价值：

- 为时尚爱好者解决“想看但不知道看什么”的启动问题。
- 把分散在书籍、影片、秀场、杂志、博物馆、品牌官网里的内容组织成中文学习路径。
- 把每周/每月趋势从“流行词堆叠”解释成可理解的审美变化、单品变化和穿搭建议。

商业/作品集价值：

- 比单纯资源导航更像真实内容产品，有明确用户痛点、内容运营机制和可持续栏目。
- 可以展示 AI 产品经理能力：资源结构化、推荐逻辑、内容生成边界、趋势分析流程、版权策略。
- 后续可扩展到账号、收藏、个性化推荐、趋势订阅、AI 穿搭顾问和品牌合作。

差异化：

- 小红书/短视频强在流行和种草，但内容碎片化、商业化强。
- Vogue/BoF/WGSN 强在专业信息，但英文门槛和订阅门槛较高。
- 豆瓣/书单强在单点推荐，但缺少系统路径和趋势更新。
- FashionAtlas 应该站在中间：用中文把全球时尚资料策展成可学习、可实践、可收藏的结构化知识。

战略判断：

这个方向具备产品竞争性，但前提是不要只做“链接跳转”，而要做“推荐理由、适用场景、观看顺序、趋势判断、个人收藏和持续更新”。

### 范围层：做什么，不做什么

建议核心功能范围：

1. 情境化资源推荐

按用户场景推荐书籍、影片、秀场、杂志和网站，例如：

- 零基础入门时尚审美
- 想看懂巴黎/米兰/伦敦/纽约时装周
- 想了解老钱风、静奢风、Y2K、Archive Fashion
- 想提高日常穿搭
- 想准备时尚专业申请/作品集
- 想了解奢侈品商业和品牌视觉

每条推荐必须包含：

- 英文原名
- 中文名称
- 简单核心概括
- 推荐理由
- 适合人群
- 观看/阅读重点
- 难度
- 时间成本
- 可到达链接
- 在哪里可以看到/获取资源
- 官方或合法免费入口；没有官方免费入口时，只保留书名/片名/杂志名、观看/购买/借阅平台建议和合法获取说明，不强行给盗版链接

2. 美学资讯与趋势分析

建立按时间组织的趋势栏目：

- 年度趋势回顾
- 月度趋势观察
- 每周穿搭趋势笔记
- 时装周趋势总结
- 单品趋势，如芭蕾平底鞋、低腰裙、皮夹克、灰色西装
- 色彩趋势，如红色、黄油黄、金属银
- 风格趋势，如 quiet luxury、office siren、balletcore

每篇趋势分析包含：

- 趋势名称
- 时间范围：年份、月份、周次
- 出现背景
- 关键单品/颜色/面料/廓形
- 来源依据：秀场、品牌 lookbook、杂志报道、搜索趋势、社交平台观察
- 适合人群和不适合场景
- 可执行穿搭建议
- 相关书籍/影片/秀场/杂志延伸阅读

真实趋势资料源建议：

- 国内穿搭观察：小红书、抖音、微博、B 站、淘宝/天猫趋势页面、品牌官方小程序/公众号公开内容，用于观察中国用户真实穿搭语境。
- 时装周与品牌：Vogue Runway、品牌官网、品牌 Lookbook、时装周官方发布。
- 媒体与行业：Vogue、Elle、Harper's Bazaar、The Business of Fashion、Highsnobiety、Dazed、i-D。
- 平台趋势：Google Trends、Pinterest Predicts、Lyst Index、Tagwalk 免费可见信息。
- 海外社交观察：Instagram、TikTok 只作为现象观察，不作为唯一依据。

趋势内容必须区分“证据”和“编辑判断”：来源负责说明趋势从哪里来，编辑判断负责说明它适合谁、怎么穿、是否值得跟。

趋势内容不做价格分析，不标注预算，不做购买导向的替代单品推荐。

3. 风格词典升级

现有风格词典保留，但要从词条升级为“风格研究页”：

- 风格解释
- 代表秀场
- 代表影片/摄影/杂志
- 入门书籍
- 日常穿搭转译
- 常见误区
- 相关趋势文章

4. 灵感板升级

从“收藏夹”升级为“个人审美档案”：

- 收藏书籍、影片、秀场、杂志、趋势文章、风格词条
- 支持按主题生成 Markdown 摘要
- 支持“我的本周穿搭灵感”或“我的品牌研究资料夹”

暂不建议 MVP 做：

- 托管视频、PDF、杂志扫描件
- 实时爬取全网趋势或绕过平台访问限制
- 用户投稿社区
- 电商导购闭环
- 价格分析、预算分层、低价替代单品推荐
- AI 自动生成未经来源支撑的趋势结论

### 结构层：信息架构怎么组织

建议将前台从“资源库为中心”改为“推荐与资讯为中心，资源库作为底层数据库”。

一级导航建议：

- 首页
- 推荐清单
- 趋势周报
- 月度趋势
- 风格词典
- 秀场路径
- 时尚书架
- 灵感板
- AI 助手

内容对象建议：

- Resource：基础资源，如网站、书、影片、杂志、秀场、课程
- Guide：情境化推荐清单，如“零基础时尚书单”
- TrendIssue：趋势周报/月报
- StyleEntry：风格词条
- RunwayShow：秀场条目
- Book：书籍条目
- Film：影片、纪录片、设计师传记、时尚电影、美学电影
- Magazine：杂志、媒体和专题栏目
- BoardItem：用户收藏

关键关系：

- Guide 可以引用多个 Resource、Book、RunwayShow、StyleEntry
- TrendIssue 可以引用 StyleEntry、RunwayShow、Book 和外部来源
- StyleEntry 可以关联趋势文章、秀场、影片和书籍
- Board 可以收藏所有内容类型

这样产品不再像目录，而像一个可以持续运营的时尚知识媒体和学习工具。

### 框架层：页面与交互怎么设计

首页首屏应回答“今天我该看什么”：

- 今日推荐：一个书/影片/秀场/杂志组合
- 本周趋势：3 个趋势卡片
- 新手入口：按目标选择，如“提升穿搭”“看懂秀场”“补时尚史”
- 搜索仍保留，但不作为唯一入口

推荐清单页：

- 左侧筛选：学习目标、难度、内容类型、时间成本、免费官方入口
- 右侧卡片：每张卡片突出“适合谁”和“为什么值得看”
- 详情页给出阅读/观看顺序，而不是只给资源列表

趋势周报页：

- 时间轴：年份 -> 月份 -> 周
- 每期固定结构：趋势摘要、关键单品、秀场/街拍/媒体来源、穿搭建议、延伸阅读
- 提供“加入灵感板”和“生成本周穿搭摘要”

资源详情页：

- 主体不是链接，而是中文学习说明
- 链接只作为“官方入口”
- 没有免费官方入口时，显示“合法获取建议”，不制造低质量跳转

AI 助手：

- 输入“我想提高日常穿搭”“我想看懂 McQueen”“我想找三本入门书”
- AI 基于资源库、推荐清单和趋势文章回答
- 输出必须引用站内条目或官方来源，避免泛泛聊天

### 表现层：视觉和内容气质

视觉方向：

- 从工具型目录进一步转向时尚编辑感。
- 使用更强的图片比例、留白、杂志式标题和清晰栏目。
- 保留黑白纸感，但减少表格感和过滤器堆叠感。

内容语气：

- 中文、清晰、有判断。
- 像一个懂时尚的编辑朋友，不像搜索引擎。
- 推荐理由要具体，不写“值得一看”这种空话。

卡片文案模板：

- 适合：零基础 / 进阶 / 穿搭实践 / 品牌研究
- 看点：你要重点看什么
- 时间：10 分钟 / 1 小时 / 长期阅读
- 入口：官方免费 / 合法预览 / 仅推荐名称

## 3. 完善后的 MVP 版本

MVP 应从“资源库 MVP”升级为“策展推荐 MVP”。

### MVP 必做模块

1. 首页改版

- 今日看什么
- 本周趋势
- 三个学习入口：提升审美、看懂秀场、改善穿搭
- 精选推荐清单

2. 推荐清单

先做 8 个清单，覆盖书籍、影片、杂志、秀场四类：

- 时尚零基础入门
- 想提升穿搭先看什么
- 看懂时装秀入门
- 时尚审美入门书单
- 时尚电影/纪录片推荐
- 杂志与媒体入门推荐
- Archive Fashion 入门
- 奢侈品牌视觉语言入门

3. 趋势周报/月份趋势

先做真实但人工策展的静态内容，不做自动爬取：

- 当前年份春夏/秋冬趋势总览
- 当前月份趋势观察
- 最近一周穿搭灵感：办公室、周末、约会、旅行四个场景
- 每期趋势列出资料来源、观察结论和可执行穿搭建议

4. 资源详情页升级

- 推荐理由
- 适合场景
- 如何阅读/观看
- 官方入口或合法获取建议
- 关联推荐清单和趋势文章

5. 灵感板升级

- 收藏推荐清单和趋势文章
- 导出 Markdown

## 4. 项目计划

### 第 1 阶段：定位与信息架构重构

目标：从“资源目录”改成“美学推荐和趋势策展平台”。

任务：

- 更新 PRD 和首页文案。
- 新增 `Guide` 和 `TrendIssue` 数据模型。
- 调整导航：推荐清单、趋势周报成为核心入口。
- 明确版权策略：官方免费入口才跳转；没有免费入口只给合法获取建议。

验收：

- 用户打开首页能立刻理解“这个网站帮我决定看什么”。
- 首页不再像资源搜索页，而像时尚策展首页。

### 第 2 阶段：推荐清单 MVP

目标：建立产品竞争力的核心内容层。

任务：

- 做 8 个推荐清单。
- 每个清单包含 5-10 个条目。
- 条目覆盖书籍、影片、秀场、杂志、网站。
- 每个条目写清楚适合谁、为什么推荐、怎么看。
- 通过公开网页检索/爬虫整理候选材料，只保存元信息、来源链接、获取渠道和自写推荐说明。

验收：

- 一个时尚小白能从任意清单开始，知道接下来 1-2 小时该看什么。
- 没有官方免费入口的内容不会出现盗版或模糊链接。

### 第 3 阶段：趋势栏目 MVP

目标：建立持续更新的理由。

任务：

- 设计趋势文章数据结构。
- 做 1 个年度趋势页、1 个真实月度趋势页、2 个真实周趋势样例。
- 每篇关联风格词典、秀场、书籍和资源。
- 增加穿搭建议模块：场景、单品、颜色、搭配公式。
- 为每篇趋势记录来源依据，至少包含 3 个可核查来源或观察线索。

验收：

- 用户能看到“本周有什么值得关注”。
- 趋势不是卖货，而是解释来源、变化和适用场景。

### 第 4 阶段：AI 助手升级

目标：让 AI 不再泛聊，而是基于站内策展内容做推荐。

任务：

- AI 输入支持目标选择：学习、穿搭、品牌研究、趋势跟踪。
- AI 输出引用 Guide、TrendIssue、Resource。
- 增加“生成我的学习清单”和“生成本周穿搭灵感摘要”。

验收：

- AI 推荐能落到站内具体内容。
- AI 不编造不存在的资源或链接。

### 第 5 阶段：作品集与上线

目标：让项目既能演示，也能作为 AI 产品经理作品集。

任务：

- 更新案例复盘：说明为什么从链接目录升级为策展产品。
- 部署到 Vercel/Netlify。
- 准备演示脚本：用户问题 -> 推荐清单 -> 趋势页 -> 灵感板 -> AI 助手。

验收：

- 3 分钟内能讲清楚用户痛点、核心功能、AI 价值、版权边界和后续商业化。

## 5. 关键风险与对策

风险 1：真实趋势内容需要持续更新。

对策：MVP 先做人工策展的真实周/月趋势，不承诺实时自动更新；每期固定引用来源依据，后续再接入半自动资料搜集。

风险 2：影片、书籍、杂志很多没有免费官方入口。

对策：没有免费入口时只做名称、推荐理由和合法获取建议，不给可疑链接。

风险 3：趋势推荐容易变成种草导购。

对策：每篇趋势都必须说明来源依据、适合/不适合场景和审美背景；不做价格分析和购买替代单品推荐。

风险 3.5：爬虫资料搜集触碰版权或平台规则。

对策：只抓取公开可访问页面的元信息、标题、链接、来源名称和少量摘要线索；不抓取全文、图片包、视频、PDF、付费内容或需要登录/绕过限制的内容。重要内容用人工改写的推荐理由和学习说明承载。

风险 4：内容量过大，难以维护。

对策：先做少量高质量清单和趋势样例，用结构证明产品能力，而不是追求数量。

## 6. 决策记录

已确认：

- 学习型时尚资料站 60%，日常穿搭趋势资讯站 40%。
- 趋势栏目做真实趋势，包含每周穿搭分析和月度趋势分析。
- 影片推荐包含纪录片、设计师传记、时尚电影和美学电影。
- 每个资源条目包含英文原名、中文名称、核心概括、可到达链接和获取渠道说明。
- 目标用户偏时尚小白/爱好者。
- 第一版真实趋势偏中国用户日常穿搭。
- 推荐清单覆盖书籍、影片、杂志、秀场四类。
- 趋势内容不标注预算，不做价格分析，只做推荐分享。
- 资料可以通过公开网页检索/爬虫整理，但只保留元信息、来源链接、获取渠道和自写策展说明。
